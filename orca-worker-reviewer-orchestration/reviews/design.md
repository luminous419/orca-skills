# DESIGN Review Policy

Common Review Policy와 함께 적용한다.

검토:
- Requirements completeness
- 실제 repository architecture와 일치 여부
- component responsibilities
- interfaces
- data flow
- error handling
- compatibility
- implementation feasibility
- testing strategy

FAIL 예:
- 핵심 requirement 누락
- repository 구조와 맞지 않는 설계
- 구현 불가능하거나 모순된 interface
- 중요한 failure handling 누락
- testing strategy 누락
- 중요한 compatibility 문제
